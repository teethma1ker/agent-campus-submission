# 01 需求说明

## 用户

内容团队运营（本次场景为单运营工作流）：每天拿到一批新素材，需要确认哪些能发、几点发、哪些需要先整改或找人确认。

## 目标

对每项素材给出：审核状态、风险原因、建议时段、待确认项、草稿保存状态；**只保存草稿，不发布**。

## 输入

- 素材 ID 与元数据（标题、格式、渠道、主题、发布时间要求、截止日、负责人、描述）；
- 发布要求（用户硬性时间，如 18:00；或 `publish_time` 缺失时请求补资料）；
- 已有排期（当日各时段占用、禁用时段）；
- 审核规则（极限词、敏感实体、类型-时段限制、营业时间）。

## 范围

做的：四工具（素材读取 / 规则检查 / 时段查询 / 草稿保存）、模型驱动的 ReAct 决策循环、执行上限、结果报告（以工具真值为准）、防虚报声明核对、CLI、测试与示例证据。

不做的：真实发布、界面、多 Agent、线上部署、真实业务数据接入（全部为合成数据）。

## 成功标准

1. 六类验收点全部通过：正常排期、信息缺失、规则风险、时段冲突、重复提交、保存失败；
2. `published` 恒为 false，草稿状态与工具返回一致，模型虚报会被标注；
3. 每个请求有完整可复现 Trace，覆盖至少两条依据工具结果调整动作的执行路径；
4. 达到步数/工具上限时返回明确的未完成状态并列出未完成项；
5. 同一素材重复提交只保留一份草稿。
